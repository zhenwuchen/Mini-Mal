# 核心业务流程

## 1. 注册与登录

1. 用户提交注册表单。
2. 应用校验邮箱格式、密码强度与确认密码。
3. 密码使用 bcrypt 哈希后保存。
4. 注册成功后跳转登录页。
5. 登录由 Credentials Provider 验证邮箱与密码。

未登录用户访问购物车、地址、订单或支付操作时，Service 返回未认证错误。

## 2. 商品浏览

1. 首页读取主要分类和精选商品。
2. 商品列表支持分类筛选、搜索与排序。
3. 商品详情读取商品、分类和同类推荐。

商品、分类和推荐均来自 Prisma + SQLite，不使用静态硬编码商品代替数据库页面。

## 3. 购物车

1. 读取当前用户购物车。
2. 添加商品时校验商品存在、上架状态与库存。
3. 调整数量时按实时库存和商品状态校验。
4. 移除只影响当前用户购物车。
5. 金额始终由服务端按数据库中的当前商品价格重新计算。

购物车写操作按用户串行化，并对 SQLite 锁冲突做有限重试。

## 4. 创建订单

订单创建在一个事务中完成：

1. 校验当前会话和 `checkoutKey`。
2. 检查同一用户的重复结算键；已存在时返回原订单。
3. 读取当前用户购物车和收货地址。
4. 读取当前商品价格、状态和库存。
5. 逐项以带条件的更新扣减库存。
6. 创建订单与商品快照，写入收货地址快照。
7. 设置 30 分钟支付截止时间。
8. 清理购物车。
9. 返回完整订单摘要。

任一关键步骤失败时事务回滚，不会留下部分订单、部分扣减或部分购物车清理。

## 5. 模拟支付

### 发起支付

1. 校验用户、订单归属和订单状态。
2. 检查订单是否超过支付截止时间。
3. 使用 provider + idempotencyKey 查找已有支付。
4. 已存在时返回原记录，避免重复创建。
5. 不存在时写入待处理模拟支付。

### 支付成功

1. 校验订单归属、支付归属、金额、币种、provider 和 method。
2. 校验订单仍为待付款、支付仍为待处理。
3. 使用数据库时间执行带截止条件的订单更新。
4. 将目标支付更新为成功。
5. 将同一订单其他待处理模拟支付更新为取消。
6. 任一步失败时回滚整个事务。

### 支付失败

1. 只允许待处理模拟支付失败。
2. 失败原因使用服务端白名单。
3. 支付更新为失败，订单保持待付款，允许后续新支付尝试。
4. 支付失败不会改变库存。

## 6. 取消订单

1. 校验当前用户拥有该订单。
2. 只有待付款订单可直接取消。
3. 条件更新订单为已取消。
4. 检查是否已有成功支付；存在成功支付时回滚取消。
5. 取消该订单所有待处理支付。
6. 按订单明细中的数量逐项恢复库存。
7. 提交订单状态、支付状态和库存变更。

重复取消返回已取消结果，不再恢复库存。并发取消通过条件更新与事务收敛，
最多恢复一次。

## 7. 超时订单

1. 外部 Cron 通过 HTTPS POST 调用内部接口。
2. Handler 校验方法、Bearer Token、请求体大小和扫描参数。
3. 扫描 Service 读取持久化游标。
4. 查询已到期且仍为待付款的订单。
5. 在批次与时间预算内逐单调用取消 Service。
6. 记录取消、跳过、失败、不一致、延迟和预算耗尽数量。
7. 推进持久化游标，使下一轮从不同位置开始轮转。

## 8. 状态与结果

订单与支付状态使用字符串枚举值，并在 Service 层做白名单校验。
超时任务响应只返回聚合数量、执行 ID 和错误类别，不返回订单号、用户或
支付敏感信息。
