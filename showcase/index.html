一个可以完整走通注册登录、商品浏览、购物车、下单、模拟支付、 取消订单与超时回收的本地业务系统。展示页面只呈现真实实现， 完整业务继续运行在本地 Node.js + SQLite 环境中。

  • Next.js 16
  • TypeScript
  • Prisma
  • SQLite
  • Tailwind CSS

01 / 核心功能

从挑选商品到回收订单，
每一段都有真实实现。

功能边界按用户操作顺序组织。页面不把规划项包装成已完成能力， 也不展示真实支付、物流或售后渠道。

01

进入与挑选

建立身份，浏览并维护待购商品。

  • 用户注册与登录

    Credentials 登录、密码哈希、会话访问与用户隔离。

  • 商品分类、列表与详情

    分类筛选、商品展示和详情数据读取。

  • 购物车管理

    添加、调整数量、移除商品，并按实时库存校验。

02

提交与支付

在事务中创建订单，模拟完整支付分支。

  • 收货地址与订单创建

    保存地址快照，扣减库存并清理购物车。

  • 模拟支付成功与失败

    支持成功、失败和重试；不调用真实支付平台。

  • 支付幂等与并发保护

    幂等键约束、状态条件更新和有限 SQLite 写锁重试。

03

退出与回收

让订单、支付和库存最终回到合法状态。

  • 取消订单与库存恢复

    状态更新、取消待处理支付与逐项恢复库存保持在同一事务。

  • 超时订单自动取消

    外部 Cron 定时触发扫描，批处理和公平轮转避免长期饥饿。

  • 内部任务接口鉴权

    独立 Bearer Token、SHA-256 摘要比较与配置错误隔离。

02 / 技术实现

把业务正确性写进数据边界。

重点不在页面数量，而在订单、支付与库存如何避免重复扣减、 重复恢复和非法状态。以下能力均可在源码与测试中找到依据。

↳

代码路径均相对于项目根目录。

  1. 01

    Prisma + SQLite 数据访问

    页面、Server Actions 与 Service 层共享 Prisma 数据访问， 本地开发与当前生产方案均使用 SQLite。

    prisma/schema.prisma · src/lib/prisma.ts
  2. 02

    支付状态机

    显式限制 PENDING、SUCCEEDED、FAILED、CANCELLED 与 REFUNDED 之间的合法迁移。

    src/lib/payment-status.ts
  3. 03

    支付幂等与并发保护

    同一幂等键复用原支付记录；完成支付时使用条件更新防止 多个请求同时成功。

    src/lib/payment-service.ts · tests/payment.test.ts
  4. 04

    订单取消事务

    取消状态、待处理支付与库存恢复共同提交；任一环节失败时 整体回滚。

    src/lib/order-cancel-service.ts · tests/order-cancel.test.ts
  5. 05

    库存恢复与重复保护

    按订单明细快照恢复数量；重复取消不会再次增加库存， 并处理并发取消。

    src/lib/order-cancel-service.ts
  6. 06

    支付截止时间保护

    下单时写入 30 分钟支付窗口，最终付款更新由数据库执行时间 校验截止边界。

    src/lib/order-policy.ts · src/lib/payment-service.ts
  7. 07

    超时扫描与公平轮转

    批次大小、时间预算与持久化游标共同限制单次任务， 让持续失败订单不会永久占住扫描起点。

    src/lib/order-expiration-service.ts
  8. 08

    内部任务 Bearer Token 鉴权

    内部接口验证 Base64URL Token、最小长度与摘要， 通过 timingSafeEqual 比较摘要。

    src/lib/internal-task-auth.ts
  9. 09

    SQLite 在线备份与恢复

    生产文档提供 SQLite Backup API 流程、校验和、完整性检查与 恢复演练步骤。

    scripts/sqlite-backup.mjs · docs/production-deployment.md
  10. 10

    Node.js 单实例部署

    当前完整系统使用单个 Next.js 进程和持久化 SQLite 文件， 由外部 Cron 每分钟调用内部任务接口。

    deploy/systemd/mini-mall.service.example

03 / 技术架构

请求、服务、数据与外部触发。

架构图只表达当前代码中的实际调用关系。完整系统不会部署到 Vercel Serverless，展示站与业务运行时彼此独立。

App Router

页面与接口同仓

商品、购物车与账户页面位于 App Router；内部任务由 Route Handler 暴露。

Consistency

一致性集中在服务层

支付、取消和超时逻辑复用 Service，不把数据库写入散落到页面组件。

Hosting

展示与运行分离

本页可以静态部署；完整电商系统仍使用 Node.js 单实例和持久化 SQLite。

05 / 本地运行

完整系统在自己的机器上运行。

展示站无需 Node.js 服务。下面的步骤用于启动完整的 Next.js 电商系统，数据库初始化和演示数据准备都需在仓库根目录执行。

不要把这些内容部署到静态展示站：

数据库文件、环境变量、AUTH_SECRET、CRON_SECRET 与业务 API。

  1. 01

    确认 Node.js

    项目要求 Node.js 22.19.x，当前范围为 >=22.19.0 <23。

    node --version
  2. 02

    安装依赖

    按锁文件安装，避免依赖版本漂移。

    npm ci
  3. 03

    准备环境变量

    从示例文件创建本地配置，并填入自己的随机 Secret。

    Copy-Item .env.example .env
  4. 04

    生成 Prisma Client

    读取现有 Schema，不修改数据库结构。

    npm run db:generate
  5. 05

    初始化全新数据库

    使用仓库中已提交的 Migration。商城演示数据按需 seed。

    npm run db:migrate:deploy
  6. 06

    启动开发环境

    打开终端提示的本地地址查看完整商城。

    npm run dev
